# Tech stack

The product stack as it is in the repository today. Each part lives in its own folder.

| Part | Folder | Language and tools |
|---|---|---|
| Phone kiosk app | `app/` | Kotlin on Android (device owner), Jetpack Compose for overlay windows, Room for the local database (schemas exported to `app/schemas/`), ktlint for style |
| Coin box firmware | `esp32_firmware/` | C++ on ESP32 (PlatformIO, `.pio/` is build output), WebSocket and HTTP, web dashboard assets embedded into `include/WebAssets.h` (generated), clang-format for style, host tests in `host_tests/` |
| Router add-on | `tools/pisoportal/` | Rust, one program on OpenWrt next to openNDS. Crypto limited to `sha2`, `hmac` and `p256`. Pre-built binaries in `tools/pisoportal/bin/` (generated by CI) |
| Router scripts | `router/` | Shell on OpenWrt (monitor, init, firewall rules such as `piso_isolation.sh`, which needs `kmod-nft-bridge`) |
| Setup program | `setup/` | Python standard library only. `cryptography` is installed only when the owner uses the owner tools. Shell installer scripts are generated from `setup/src/` |
| Website | `website/` | Static HTML, CSS and JavaScript. Signed update feeds in `website/update/` and `website/flash/` (generated by CI). Vendored JS bundles listed in `website/js/VENDORED.md` |
| Owner tools | `scripts/` | Python, run on the owner's own computer. Make keys, cards and posters; sign updates; check a release with `verify_release.py` |
| Protocol | `protocol/` | Shared test vectors, generated by `protocol/gen_vectors.py`. Box and phone must change together |
| Docs | `docs/` | Markdown |

## Build, test and release

- **CI:** GitHub Actions. `quality.yml` runs checks on each branch; `firmware-images.yml`, `build-apk.yml` and `publish-router.yml` build and sign releases.
- **Branches:** `beta` for work, `main` for production.
- **Checks:** the commands per area are in `CONTRIBUTING.md`, "Before you open a pull request." `bash scripts/check_security_rules.sh` runs on every change.
- **Generated files** are never edited by hand. The sources and the regenerate command are listed in `CLAUDE.md`, section 4.

## Not in this repo

- **Print server:** its own project. This repo only specifies how the router talks to it (`docs/api/`).

## Rules for adding to this stack

- Prefer what is already here. A new language or library needs a reason written down in the change.
- No new cryptography outside the existing libraries listed above.
- No secret, key or password in the repository.
