## Intent
A shop owner runs PisoWiFi on a cheap router, some with only 16 MB of flash. The owner asked: (1) confirm the setup works, (2) let the owner choose the product (PisoWiFi, PisoPhone or both) and install only what that product needs, (3) make the full PisoWiFi, with every feature, fit on a 16 MB router. Instead of a cut-down program, the flash goes to PisoWiFi: the 1.6 MB installer copy no longer sits on flash. Nothing here may cost a customer money or time.

## Facts (checked in the code on 2026-10-22; nothing measured on hardware)
1. **Sizes:** the router program `tools/pisoportal` is 919 KB (armv7) to 1091 KB (mips) (router 1.5.16); the installer `setup/piso-setup*.sh` is about 1617 KB (the program embedded as base64). Budgets (`router/tests/test_footprint.py`): program 1200 KB, installer 1700 KB.
2. **What a PisoWiFi install keeps on flash today:**
   - `/usr/bin/pisoportal` (about 1 MB) and `/usr/sbin/piso-setup` (the installer without its embedded program, `setup/src/40-files.sh:88`);
   - `/root/piso-setup.sh`: the **whole installer, about 1.6 MB**, saved by the one-line installer (`setup/install.sh`: `DIR="${PISO_INSTALL_DIR:-/root}"` line 23, saved at line 142) **and never deleted**;
   - `/root/piso-update-backup` after each update, until the update has proven itself (`setup/src/90-updates.sh:12`);
   - packages `opennds curl ca-bundle jsonfilter` (`setup/src/20-preflight.sh:45-49`), `libmicrohttpd-no-ssl` (line 55). `kmod-nft-bridge` (needed by the guest and kiosk isolation, `router/piso_isolation.sh`) is **not** installed by the setup: it only warns when the module is missing (`setup/src/75-checks-stage2.sh:15`);
   - the data folder `/etc/coinslot.d` (roll, `revenue.csv`, ledger, vouchers, wheel files).
   OpenWrt's jffs2 stores files compressed; by how much is not measured.
3. **Updates already use RAM:** an update works in `/tmp` unless free memory (`MemAvailable`) is under 24000 KB, then in `/root` on flash (`setup/src/96-space-backup.sh:15-25`: `mem_available_kb`, test hook `PISO_MEM_KB`; `work_base`, hook `PISO_LOW_MEM_KB`).
4. **The one-line installer's two paths:** with `--yes` (used by `pisophone_setup.py`) it runs the saved file at once (`setup/install.sh:153`). By hand, on a router still at its factory address, it moves the router to 10.0.0.1 (a network restart, not a reboot: `/tmp` survives), the SSH session ends, and the owner is told to log in again and type `./piso-setup.sh` (`setup/install.sh:73-87`). The same instruction is in `docs/DEPLOY.md`, `docs/REAL_WORLD_TESTING.md`, `docs/RELEASE.md`, `docs/ROUTERS.md`.
5. **Writable flash on a 16 MB router:** reports give about 6 to 8 MB free after a fresh OpenWrt install with LuCI (some boards about 4 MB). The installer reads only `df -k /overlay` today; nothing reads the chip size.
6. **What on the router is PisoPhone-only:** the rental phones' hidden Wi-Fi `PisoKiosk-xxxx` (`wireless.kiosk_<radio>`, on the `lan` network, `setup/src/30-router-settings.sh:42-50`), its password `KIOSK_PASS` (asked or made in `setup/src/98-setup-flow.sh:63`, `:100`), handing that name and password to the coin box for its "Set up a phone" link (`setup/src/50-coin-box.sh:143-170`, `sync_kiosk_wifi`, run at install, by `piso-setup` (`80-commands.sh:212`) and hourly (`90-updates.sh:97`)), the agreement and stage-2 checks of that Wi-Fi (`70-agreement.sh:24,37`, `75-checks-stage2.sh:6`), its lines in the summary, the plan and the owner handout (`60-summary.sh:11`, `98-setup-flow.sh:74,79`, `95-owner-tools.sh:76`), and the command `piso-setup kiosk-wifi` (`98-setup-flow.sh:156`).
7. **Shared by both products (stays in every install):** the coin box, its hidden Wi-Fi `box_ap` on the `lan` network (`30-router-settings.sh`, after line 60), the box link and payments (`boxlink.rs`), the coin box's admin page in the console (`boxview.rs`, the tab labelled "Rental phones", `console.html:60,68`), the `lan` network 10.0.0.0/24, and both isolation tables: `piso_guest` keeps guests apart; `piso_kiosk` also keeps devices on `lan` Wi-Fi ports (the coin box's) away from the router's login pages (`router/piso_isolation.sh:1-16`).
8. **PisoWiFi features (all kept):** coin page, vouchers, pause (`config.rs:24-40`), endurance (`config.rs:174-176`), HyperSpeed (`pricing.rs:131`, `fair.rs`), the wheel (off until the owner confirms the warning), the free mini-game, "send a file to the owner", the console.
9. **Paid time survives a power cut:** the roll file (`roll.rs:1-4`, temporary file then rename, under the process lock), read back at start; unit test `roll.rs:422`; feature 001. Not tried on hardware (RS32).
10. **Settings files:** the installer's own settings are `/etc/piso-setup.conf` (`CONF`, `00-header.sh:48`; `conf_get` / `conf_set` in `10-settings.sh`); the program's settings are `/etc/coinslot.conf`, written by `write_coinslot_conf` (`40-files.sh:105`).
11. **The setup program:** `setup/pisophone_setup.py` has a web page (default) and `--cli`; `--phone-only` (line 5450, code from 3461) sets up a PisoPhone-only coin box on the shop's normal router with no router software; otherwise it sets up the router through the one-line installer with `--yes`.
12. **The 360 T6GS (the owner's test router):** MT7621AT, a 16 MB SPI NOR chip and a 128 MB NAND chip; most community builds run from the NAND, one from the 16 MB NOR only. No official OpenWrt or ImmortalWrt support; `kmod-nft-bridge` for its kernel may be missing from the official feed.
13. **Baseline:** `cargo test` in `tools/pisoportal`: 141 passed (2026-10-22, `main` = `beta` code).

## Decisions (final; from the owner's rounds 1 to 7, see History)
1. **Product:** the setup program asks PisoWiFi, PisoPhone or both, with nothing preselected. PisoPhone only installs nothing on a router (as today).
2. **One program for every router:** the full PisoWiFi program with every feature (fact 8). No `small` build, no second feed (parked; if a router turns out too small, that becomes its own feature).
3. **Installer copy in RAM:** the one-line installer saves the installer in `/tmp` when free memory is at least 24000 KB (the rule updates use, fact 3), otherwise in `/root`.
4. **No installer copy left:** after a successful install the setup deletes the copy it was started from (`/tmp/piso-setup.sh` or `/root/piso-setup.sh`); after a failed install the copy stays, so the owner can run it again.
5. **PisoWiFi-only router:** everything of facts 7 and 8, nothing of fact 6. The console tab that shows the coin box's page is labelled "Coin box" on a PisoWiFi-only router and "Rental phones" on a both router.
6. **Existing routers:** an update changes nothing about the product; a router installed before 1.5.17 is a both router. Only the owner, re-running the installer with a product, switches a router between both and PisoWiFi only.
7. **Fits:** at least 2 MB (2048 KB) free on `/overlay` after the install. The summary warns below that.
8. **Room for an update:** on a router whose updates work on flash (fact 3), the summary also warns when free flash is under 2048 KB + 1700 KB (the installer's size budget).
9. **Flash chip:** the setup measures and prints the chip that holds the writable data (criterion 4); nothing is decided by it in this feature.
10. **Size proof:** CI numbers and the plan's estimate first; then the owner's 360 T6GS (hardware check, not run until the owner does it).

## Success criteria (each becomes a line in `validation.md`; test file in brackets)
1. **Baseline.** Before any change, all pass and their counts are recorded: `cargo test --locked --release` and `python3 tests/test_flow.py` in `tools/pisoportal`; `router/tests/test_setup.py`, `test_pisophone_setup.py`, `test_setup_web.py`, `test_setup_tools.py`, `test_setup_phone_web.py`, `test_phone_only.py`, `test_install.py`, `test_selfupdate.py`, `test_footprint.py`; `bash scripts/check_security_rules.sh`. A failure is reported to the owner before anything else.
2. **Installer copy in RAM** [`router/tests/test_install.py`]. With `PISO_MEM_KB` at 24000 or more the one-line installer saves to `/tmp/piso-setup.sh`; under 24000 to `/root/piso-setup.sh`; `PISO_INSTALL_DIR` overrides both. The sha256 check is unchanged. The factory-address message says to log in again and run `sh <the saved path>`, and, when it is in `/tmp`, "if the router restarts before that, run the one-line installer again". `--yes` runs the saved file as today. The four docs of fact 4 say the same.
3. **No installer copy left** [`router/tests/test_install.py`, `test_setup.py`]. The setup turns `$0` into an absolute path (`install.sh` starts it as `./piso-setup.sh` from inside `$DIR`, `setup/install.sh:150-156`); when that path is `/tmp/piso-setup.sh` or `/root/piso-setup.sh`, the file is deleted after a successful install; after a failed install it is still there; `/usr/sbin/piso-setup` and an update still work afterwards. A setup started from any other path (a copied file, a branch test) deletes nothing.
4. **Flash measurement** [`router/tests/test_setup.py`, through the test hooks]. `flash_class` in this order:
   1. Look in `PISO_MTD_FILE` for a partition named `rootfs_data`, else `ubi`. Neither: step 4.
   2. Its `type` in `PISO_MTD_SYSFS/mtdN/type`: `nand` or `mlc-nand` gives `large <bytes> nand` (that partition's size).
   3. `nor`: the chip size is the size of a `nor` partition named `fullflash` or `ALL` if listed, else the largest `offset + size` over the `nor` partitions (`mtdN/offset`, `size`, `type`). At most 16,777,216 bytes: `small`, else `large` (`<how>` = `nor`). Never add sizes; never compare offsets of different chips.
   4. No `rootfs_data` or `ubi` (x86, virtual machines, eMMC, a NAND board that names its UBI partition differently): the total of `/overlay` (or `/`) over 16384 KB is `large <bytes> disk`, else `small <bytes> disk`. (A writable area bigger than 16 MiB cannot sit on a 16 MiB chip.)
   5. Anything unreadable or not as above: `small - odd`.
   Expected answers (one test each): 8 MiB NOR small; 16 MiB NOR small; 32 MiB NOR large; 16 MiB NOR with overlapping `firmware`, `kernel`, `rootfs`, `rootfs_data` small; a `fullflash` of 16 MiB small; the 360 T6GS from NAND (bootloader NOR partitions, `ubi` on 128 MiB NAND) large; the 360 T6GS NOR-only build small; a 128 MiB NAND-only board large; no MTD and a 4 GB disk large; eMMC with a bootloader-only MTD and a 4 GB root large; a NAND board whose UBI partition is named `UBI_DEV`, with a 90 MiB overlay, large; no MTD and a 12 MiB disk small; a missing `offset` file `small - odd`; a garbled `/proc/mtd` `small - odd`.
5. **Free space in the summary** [`router/tests/test_setup.py`, stub `df`, `PISO_MEM_KB`]. The setup summary and `piso-setup space` print the `flash_class` line and the free KB on `/overlay`. Under 2048 KB: "less than 2 MB free: records and updates may not fit". With `PISO_MEM_KB` under 24000 and free KB under 2048 + 1700 (the installer's size budget, `test_footprint.py`): "too little free flash to download an update". Otherwise no warning.
6. **Product choice in the setup program** [`router/tests/test_pisophone_setup.py`, `test_phone_only.py`, `test_setup_phone_web.py`, `test_setup_web.py`]. The web page and `--cli` ask PisoWiFi, PisoPhone or both, nothing preselected. `--yes` without `--product` or `--phone-only` stops with "choose the product: --product wifi, phone or both" and changes nothing. `phone` runs the existing `--phone-only` path. `wifi` and `both` run the router setup as today with `SHOP_PRODUCT` set: it is added to `ANSWER_ORDER` (`pisophone_setup.py:93`), which is how the answers reach the router (`setup_command` exports them); the rental-phone Wi-Fi password is asked and shown only for `both` (sent empty for `wifi`).
7. **A PisoWiFi-only router** [`router/tests/test_setup.py`, `test_setup_tools.py`; a `tools/pisoportal` test for the label]. With `SHOP_PRODUCT=wifi`: no `wireless.kiosk_*` section; no `KIOSK_PASS` asked, made or stored; the coin box is not given a kiosk name or password, at install or hourly; the agreement and stage-2 checks skip the kiosk Wi-Fi and report no problem for its absence; the summary, the plan and the handout have no rental-phone Wi-Fi lines; `piso-setup kiosk-wifi` answers "this shop has no rental phones (PisoWiFi only)"; no `KIOSK_PASS` in `/etc/piso-setup.conf`; the coin box Wi-Fi, guest Wi-Fi, both isolation tables (`piso_kiosk` still covers the coin box's Wi-Fi port: `WIFI_PORTS` are the Wi-Fi ports of `br-lan`, `router/piso_isolation.sh:76-100`), the portal and the console are as on a both router; the console tab reads "Coin box". With `SHOP_PRODUCT=both` or missing: everything exactly as today (the existing tests pass unchanged).
8. **Switching the product keeps everything else** [`router/tests/test_setup.py`]. On an installed router, re-running the installer with `SHOP_PRODUCT=wifi` removes the `kiosk_*` Wi-Fi after the warning "rental phones on <name> will lose their Wi-Fi" (asked interactively, accepted with `--yes`); and deletes `KIOSK_PASS` from `/etc/piso-setup.conf`; with `SHOP_PRODUCT=both` it adds them with a new password; without `SHOP_PRODUCT` the product stays. An update never changes it. In every case a data folder holding a paid session, a sale, ledger lines and an unused voucher is byte-for-byte the same afterwards, and every other setting in both settings files is kept.
9. **Full PisoWiFi kept** [`cargo test`, `tools/pisoportal/tests/test_flow.py`, `test_wheel*.py`]. Every existing pisoportal test passes unchanged; no feature is removed.
10. **Does the full install fit?** [`validation.md`, plan group 2]. For mipsel: each file of fact 2 with its size and its estimated size on flash (gzip -6 of each 4 KB piece, as jffs2 stores it), the packages' `Installed-Size` from the OpenWrt package index, with the installer copy not on flash (decisions 3, 4); compared with 6 to 8 MB writable and decisions 7 and 8. Marked as an estimate. If it does not fit, the owner decides on a follow-up feature; this feature still ships.
11. **Hardware** [`docs/REAL_WORLD_TESTING.md`, a new check, "not run"]. On the 360 T6GS: (a) on a NAND build `flash_class` says large; (b) on the NOR-only build it says small, the full PisoWiFi installs as PisoWiFi only, the installer copy was in `/tmp` and is gone, at least 2 MB is free on `/overlay` (the number goes in `validation.md`), a coin, a pause, HyperSpeed and a voucher work, a power cut keeps paid time, there is no `PisoKiosk` Wi-Fi and the console tab reads "Coin box"; (c) whether `kmod-nft-bridge` is present or can be installed on its community build (the setup warns when it is missing, fact 2). First readings: `cat /proc/mtd`, `grep . /sys/class/mtd/mtd*/type /sys/class/mtd/mtd*/offset`, `df -k /overlay`, `cat /etc/openwrt_release`, `uname -r`, `free`.
12. **Gates.** `bash scripts/check_security_rules.sh`; `cargo fmt --check`, `cargo clippy --locked --release --all-targets -- -D warnings`, `cargo test --locked --release` in `tools/pisoportal`; the Python tests of criterion 1; `python3 tools/build_piso_setup.py --check`.
