## Intent
A shop owner runs PisoWiFi on a cheap router. Some have 16 MB of flash, and the full install may not fit with room left for the money records, logs and updates. The owner asked: (1) confirm the setup works, (2) let the owner choose the product (PisoWiFi, PisoPhone or both), (3) measure the flash and give a router of 16 MiB or less a smaller image that keeps the features that matter. Nothing here may cost a customer money or time.

## Facts (checked in the code on 2026-10-22; nothing measured on hardware)
1. **Program and installer sizes:** the router program `tools/pisoportal` is 919 KB (armv7) to 1091 KB (mips) (`specs/RELEASE_STATE.md`, router 1.5.16); the wheel is about 64 KB of it. The installer `setup/piso-setup*.sh` is about 1617 KB (the program is embedded in it as base64); budgets in `router/tests/test_footprint.py`: program 1200 KB, installer 1700 KB.
2. **What PisoWiFi keeps on the router's flash** (more than the earlier estimate counted):
   - `/usr/bin/pisoportal` (the program, about 1 MB);
   - `/usr/sbin/piso-setup` (the installer without its embedded program, `setup/src/40-files.sh:88`);
   - `/root/piso-setup.sh`: the **whole installer, about 1.6 MB, saved by the one-line installer** (`setup/install.sh`, `DIR=/root`, line 142) **and never deleted**;
   - `/root/piso-update-backup` after each update: the previous files, until the update has proven itself (`setup/src/90-updates.sh:12`, `96-space-backup.sh` `cmd_space`);
   - an update works in `/tmp` (RAM) unless the router has less than 24000 KB of free memory; then it works in `/root`, on flash (`96-space-backup.sh:22-25`);
   - packages: `opennds curl ca-bundle jsonfilter` (`setup/src/20-preflight.sh:45-49`), `libmicrohttpd-no-ssl` (line 55), `kmod-nft-bridge` for the isolation rules (`setup/src/75-checks-stage2.sh:15`);
   - the data folder `/etc/coinslot.d` (roll, `revenue.csv`, ledger, vouchers, `wheel/`, `wheel-confirm.txt`).
   OpenWrt's flash file system (jffs2) stores files compressed, so the space used is less than the file sizes; by how much is not measured.
3. **Writable flash on a 16 MB router:** reports give about 6 to 8 MB free after a fresh OpenWrt install with LuCI (older releases; some boards about 4 MB). The installer reads only `df -k /overlay` today (`96-space-backup.sh`); nothing reads the chip size.
4. **The owner's test router, a Qihoo 360 T6GS:** MediaTek MT7621AT, a 16 MB SPI NOR chip (bootloader) and a 128 MB NAND chip. Most community builds run from the NAND; one community build runs from the 16 MB NOR only. No official OpenWrt or ImmortalWrt support. On a community build the official package feed may have no `kmod-nft-bridge` for its kernel, so the isolation rules may not install (with either image; the setup already stops when a package cannot be installed).
5. **Optional features are always built in today:** the wheel (`wheel.rs`, `wheel_run.rs`, `wheel_limits.rs`, `wheel_spin.rs`, `wheel_gate.rs`, `wheel.html`), the mini-game (`game.rs`, `game.html`, `/game` routes in `http.rs`) and the coin-box view (`boxview.rs`, started at `console.rs:787`). `tools/pisoportal/Cargo.toml` has one feature today, `test-owner-key` (tests only).
6. **Kept features in the code:** pause (`config.rs:24-40`), endurance (`config.rs:174-176`), HyperSpeed (`Plan::Hyper`, `pricing.rs:131`, fair use `fair.rs`).
7. **Paid time survives a power cut:** paid sessions are in the roll file (`roll.rs:1-4`, written to a temporary file and renamed, under the process lock), read back at start; unit test `roll.rs:422`; feature 001 (clock jump, `core.rs:256`). Not tried on hardware (RS32).
8. **The wheel's spin journal:** a spin is written to `/etc/coinslot.d/wheel/<id>.spin` (`state=intent`) before the session changes and marked `state=done` after (`wheel_spin.rs:1-4`, `:201-205`). Open spins are finished or voided by `wheel_spin::recover`, which the program's maintenance runs at start and then every `FAIR_INTERVAL_SECONDS` (default 60 s) (`core.rs:1533-1540`, `main.rs:177`, `fair.rs:64`, `config.rs:202`). The wheel is on only while `/etc/coinslot.d/wheel-confirm.txt` exists; turning it off in the console removes it (`wheel_gate.rs:1-3`, `turn_off` line 61).
9. **Delivery today:** one installer per CPU family with its program embedded (`tools/build_piso_setup.py`: `setup/piso-setup.sh` for mipsel, `setup/piso-setup-<family>.sh` for mips, aarch64, armv7, x86_64), each with a `.sha256`; the one-line installer `setup/install.sh` (copied to `website/install.sh` by `build_piso_setup.py`) picks the file by `DISTRIB_ARCH` (lines 117-131). Signed feed per family: `website/update/router.json` + `router-setup.sh` for mipsel, `website/update/<family>/router.json` + `router-setup.sh` for the others (one `version`, `sha256`, `size`, `rollout`, `sig` each). The hourly update (`setup/src/90-updates.sh:98-100`) fetches `router.json` of its family. Built by `router-program.yml`, signed and published by `publish-router.yml`, checked by `scripts/verify_release.py`.
10. **Settings:** the installer keeps its settings in `/etc/piso-setup.conf` (`CONF`, `setup/src/00-header.sh:48`), read and written with `conf_get` / `conf_set` (`setup/src/10-settings.sh`).
11. **PisoPhone only already exists:** `pisophone_setup.py --phone-only` (terminal) sets up the coin box on the shop's normal router over USB, no router software (`setup/pisophone_setup.py:5450`, code from line 3461). The setup program also has a web page (default) and `--cli`.
12. **Baseline:** `cargo test` in `tools/pisoportal`: 141 passed (2026-10-22, on `main`'s code, which equals `beta`'s).

## Decisions (final; from the owner's rounds 1 to 5, see History)
1. **Product:** the setup program on the computer asks PisoWiFi, PisoPhone or both. No fixed default.
2. **Small router:** the flash chip that holds the writable data is 16 MiB (16,777,216 bytes) or less. RAM is not checked.
3. **Small image:** the same program built with the Cargo feature `small`, which compiles out the wheel (and its recent-spins view), the free mini-game and the coin-box view (the console's Rental phones tab). Everything else stays: coins and payments, the portal, openNDS, pause, endurance, HyperSpeed, vouchers, paid time across power cuts, the console settings, the isolation rules, backups, updates, LuCI on 8080.
4. **Unpaid visitor on a small router:** sees the coin page with pause, HyperSpeed and endurance as today, and no wheel or game button. Large routers keep the mini-game (and the wheel when the owner turns it on).
5. **Delivery:** a second signed installer and feed entry per CPU family, next to the full one, signed with the same owner key (names below).
6. **Routers already installed:** an update never changes the image. Only a new install, or the owner running the one-line installer again with an image choice, changes it.
7. **No switch with an open spin:** switching a router to the small image is refused while the wheel is on or a spin is not `state=done`.
8. **Fits:** the full install "fits" when at least 2 MB (2048 KB) is free on `/overlay` after it.
9. **The owner can choose:** `auto` (the measurement decides), `full` or `small`.
10. **Size proof:** CI numbers first; then the owner's 360 T6GS on its 16 MB NOR build (hardware check, not run until the owner does it).
11. **Measure before building the small image:** plan group 2 estimates whether the full install fits (decision 8); the owner then decides whether groups 5 to 10 run or the small build is parked.

## Owner decisions still open (round 6; needed before plan group 2 reports, not before group 1)
- **D1. The installer copy left on flash.** `/root/piso-setup.sh` (about 1.6 MB, fact 2) stays on the router after every install. Deleting it once the setup has finished would free more flash than the whole small image saves (the wheel, game and coin-box view are about 0.1 MB). Proposed: add to this feature, for every router: the setup deletes `/root/piso-setup.sh` after a successful install (the installed `piso-setup` command and the update do not need it).
- **D2. Room for an update.** On a router with less than 24000 KB free memory, an update downloads the 1.6 MB installer to flash and keeps a backup of the old files (fact 2), so 2 MB free may not be enough to update. Proposed: decision 8 stays 2 MB; the summary also warns when free flash is under 2 MB + the installer size on a router whose updates work on flash.

## Success criteria (each becomes a line in `validation.md`; test file in brackets)
1. **Baseline.** Before any change, all of these pass and their counts are recorded: `cargo test --locked --release` and `python3 tests/test_flow.py` in `tools/pisoportal`; `router/tests/test_setup.py`, `test_pisophone_setup.py`, `test_setup_web.py`, `test_setup_tools.py`, `test_setup_phone_web.py`, `test_phone_only.py`, `test_install.py`, `test_footprint.py`; `bash scripts/check_security_rules.sh`. A failure here is reported to the owner before anything else.
2. **Flash measurement** [`router/tests/test_setup.py`, through the test hooks]. `flash_class` follows these steps in order:
   1. Look in `PISO_MTD_FILE` for a partition named `rootfs_data`, else one named `ubi`. If neither exists, go to step 4.
   2. Read that partition's `type` in `PISO_MTD_SYSFS/mtdN/type`. `nand` or `mlc-nand`: `large <bytes> nand` (bytes: that partition's size).
   3. `nor`: the chip size is the size of a partition named `fullflash` or `ALL` whose type is `nor`, if listed; otherwise the largest `offset + size` over the partitions whose type is `nor` (`PISO_MTD_SYSFS/mtdN/offset`, `size`, `type`). 16,777,216 bytes or less: `small`, else `large` (`<how>` = `nor`). Never add sizes up (partitions overlap); never compare offsets of different chips.
   4. No `rootfs_data` or `ubi` partition (x86, virtual machines, eMMC boards): the total size of `/overlay` (or `/`; `PISO_OVERLAY_KB` in tests) over 131072 KB is `large <bytes> disk`, otherwise `small <bytes> disk`.
   5. Anything unreadable or not as above (no `type` or `offset` file, a size that is not a number): `small - odd`.
   Expected answers (each a test): 8 MiB NOR: small; 16 MiB NOR: small; 32 MiB NOR: large; 16 MiB NOR with overlapping `firmware`, `kernel`, `rootfs`, `rootfs_data`: small (the sum would say large); a NOR board listing `fullflash` of 16 MiB: small; the 360 T6GS from NAND (16 MiB NOR partitions for the bootloader, `ubi` on a 128 MiB NAND): large; the 360 T6GS on its NOR-only build (`rootfs_data` on the 16 MiB NOR, no `ubi`): small; a 128 MiB NAND-only board: large; no MTD and a 4 GB disk: large; an eMMC board whose MTD holds only the bootloader and a 4 GB root: large; no MTD and a 100 MiB disk: small; a missing `offset` file: small - odd; a garbled `/proc/mtd`: small - odd.
   The setup summary prints the line and the free KB on `/overlay`.
3. **Power cuts and the spin journal** [`tools/pisoportal` unit tests; `router/tests/test_setup.py`]. The existing roll tests pass on both builds (`cargo test` and `cargo test --features small`). Switching to the small image (criterion 14) is refused, with nothing changed and the reason "turn the wheel off in the console, wait two minutes and run the installer again", while `/etc/coinslot.d/wheel-confirm.txt` exists or any `/etc/coinslot.d/wheel/*.spin` file has no line `state=done`. With the wheel off and every spin done, the switch goes ahead. (The full program's maintenance finishes open spins by itself, fact 8; no new program command is needed.)
4. **Sizes** [CI log, `validation.md`]. CI prints, per family, the full and the small program size and the saving in KB, and the size of each installer. Budgets in `router/tests/test_footprint.py`: each small program is smaller than the full one of its family and at most 1200 KB; each small installer at most 1700 KB.
5. **Kept features work on the small image** [`cargo test --features small`; `tools/pisoportal/tests/test_flow.py` against a small build]. A coin credits time once and the payment is recorded before the credit; pause, endurance, HyperSpeed and vouchers behave as on the full build. The isolation rules are not changed by this feature (their loading on a router is part of criterion 8).
6. **Removed features are gone on the small image** [`tools/pisoportal` tests and `test_flow.py` against a small build]. `/game`, the wheel's routes and the coin-box view answer 404; the console shows no Rental phones tab and no wheel settings; the coin page and the *You are online* page have no wheel or game button or link; the small binary does not contain the `<title>` text of `wheel.html` or `game.html`. Wheel files left in `/etc/coinslot.d` by a full image are ignored and kept.
7. **Product choice in the setup program** [`router/tests/test_pisophone_setup.py`, `test_phone_only.py`, `test_setup_phone_web.py`, `test_setup_web.py`]. The web page and `--cli` ask PisoWiFi, PisoPhone or both, with nothing preselected. `--yes` without `--product` (or `--phone-only`) stops with "choose the product: --product wifi, phone or both" and changes nothing. `phone` runs the existing `--phone-only` path and touches no router. `wifi` and `both` run the router setup as today and pass `--image` (default `auto`) to the router as `ROUTER_IMAGE`. The pages and docs that show a setup command (`website/start/`, `setup/README.md`) show the new choice.
8. **Hardware** [`docs/REAL_WORLD_TESTING.md`, a new check, "not run"]. On the 360 T6GS: (a) on a NAND build `flash_class` says large; (b) on the NOR-only build it says small, the small image installs, at least 2 MB is free on `/overlay` afterwards (the number goes in `validation.md`), a coin, a pause and HyperSpeed work, a power cut keeps paid time, the hourly update stays on the small feed, and there is no wheel, mini-game or Rental phones tab; (c) whether `kmod-nft-bridge` installs on its community build. First readings: `cat /proc/mtd`, `grep . /sys/class/mtd/mtd*/type /sys/class/mtd/mtd*/offset`, `df -k /overlay`, `cat /etc/openwrt_release`, `uname -r`, `free`.
9. **Gates.** `bash scripts/check_security_rules.sh`; in `tools/pisoportal`: `cargo fmt --check`, `cargo clippy --locked --release --all-targets -- -D warnings` and `cargo test --locked --release`, each also with `--features small`; the router and setup Python tests of criterion 1; `python3 tools/build_piso_setup.py --check`. `.github/workflows/quality.yml` runs the `--features small` test and clippy in the same job as the full ones, so CI tests what ships.
