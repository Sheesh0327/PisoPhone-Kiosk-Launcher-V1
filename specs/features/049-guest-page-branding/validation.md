## Group 2: the signed brand pack and the public data (`brandpack.rs`, `brand.rs`, `http.rs`, `main.rs`)
- **Red first:** 10 pack tests failed against stubs, then 3 public-data tests (ledger). **Green:** whole crate `cargo test --release` **169 passed, 0 failed** (156 before); `cargo fmt --check` and `cargo clippy --release --all-targets -- -D warnings` clean.
- **The pack** (`pisophone-brand-v1`, six lines, signed text `pisophone-brand-v1|<logo sha256>|<logo size>|<picture sha256 or ->|<picture size>`): accepted when signed by the owner key, made in Rust or by Python's `cryptography` (a Python-signed vector is in the tests); refused with a reason for a changed byte, another image under the old signature, a changed size, a picture added after signing, a wrong key, a missing or damaged key, a router-update signature or a `pisophone-brand-v2` text, an SVG or GIF or HTML that starts like a PNG even when the owner signed it, 513 pixels or 0, 64 KB + 1, a PNG with no IHDR first or no end or trailing bytes, a JPEG with no end or no frame header, a bad header line, extra lines, bad base64, a file over 300 KB. Exactly 512 by 512 pixels and exactly 64 KB are allowed; a Windows line ending is fine.
- **Install** is all or nothing: image files first, `images.txt` last, then the old pack's files are removed; a refused pack creates nothing; a changed image file is never served; `images.txt` can only name files this program made (a path in it is never followed).
- **Public data:** `GET /brand.json` (fixed shape, no sign-in, only what guests see; exactly `{"v":1,"branded":false}` until something is published), `GET /brand/logo` and `/brand/picture` (404 on an unbranded router, nosniff, a CSP that lets the file do nothing but be a picture). `tools/pisoportal/tests/test_brand_public.py`: **20 checks, 0 failures** (added to Code quality). This end-to-end test was written together with the routes, not before them; the Rust tests it relies on were red first.
- **Commands:** `pisoportal brand-verify <pack>` and `brand-install <pack>` (exit 0 / 1 / 2). With the real owner key built in, a pack signed by the throwaway test key is refused ("the signature is not the owner's") and nothing is created in the data folder (tried on the release binary). Signing and installing a real pack end to end comes in group 3 with the owner tool.
- **Nothing else moved:** `test_flow.py` **216 checks, 0 failures**; `test_page_golden.py` **24 checks, 0 failures** (today's page unchanged); no money-path file changed (`git diff --stat`: `brand.rs`, `http.rs` routes, `main.rs` commands, new `brandpack.rs`).

## Group 3: the owner's tool `scripts/make_brand_pack.py`
- **Red first:** `test_make_brand_pack.py` crashed against a stub tool (ledger). **Green:** 34 checks, 0 failures; `ruff` clean.
- **What the tool does:** reads the owner's private key (outside the repository), checks the logo (and an optional picture) with the same rules as the router (PNG or JPEG only, whole, at most 64 KB and 512 by 512 pixels), signs the six-line pack, writes it with a `.tmp` rename, and refuses with a reason and writes nothing for: an SVG, a GIF, 513 pixels, over 64 KB, a PNG cut short, a missing file, a bad picture, a private key that is **not the key built into the router program** (no router would take the pack; `--no-key-check` skips it), a private key **kept inside the repository**, and an existing pack (unless `--force`). 512 by 512 and exactly 64 KB are accepted. The signature verifies with the public key over the documented text.
- **The tool and the router agree, end to end:** `tools/pisoportal/tests/test_brand_pack.py` builds the real router program with the test-only `test-owner-key` feature, makes packs with the tool, and has the router verify and install them: **19 checks, 0 failures**. It accepts a good pack (with and without a picture); refuses a changed picture byte, a changed size, another logo under the old signature, a half pack, a pack signed by another key, a router holding another owner's key, and the production key built into the program (which refuses a throwaway key's pack); a refused pack installs nothing; a newer pack replaces the older files; and the portal then serves the owner's logo and picture byte for byte at `/brand/logo` and `/brand/picture`. (This end-to-end test was written after both sides existed; each side was red first.)
- **CI:** both tests run in Code quality (the tool's own test with the other script tests; the round trip with the router-update tests, sharing `$HOME/test-target`).
- **Cleaned up:** the pack's "192 KB in all" ceiling could never be reached (two pictures of at most 64 KB are 128 KB), so the router no longer carries that dead check and the spec now says 128 KB; the 300 KB file limit still stops anything bigger. `cargo test --release` **169 passed**, fmt and clippy clean.

## Group 4: the branded guest page
- **Red first:** `cargo test --release f049_` against stubs: 11 failed, 29 passed (ledger). **Green:** 40 `f049_*` tests, 181 router tests in all; `cargo fmt --check` and `clippy -D warnings` clean.
- **How it works:** `brandpage.rs` `decorate()` takes the page the program always builds and changes only eight named places (title, two icons, header, welcome block, the line under the coin button, footer, end of head). If one of them is missing or occurs twice (someone edited `page.html`), nothing is decorated and the log says why: guests get the plain page, never half of one. `page.html` and `base.css` are untouched, so the unbranded page is byte for byte today's (golden hash, 24 checks, 0 failures).
- **What a shop sees (English, Classic only; layouts and Filipino are group 5):** the shop's name in the tab title and header (tagline next to it), the logo only if installed, the welcome text in place of the standard line, the promo above the welcome (idle page only), the house rules under the coin button (idle page only), contact and hours in the footer (every state), colours from the palette and accent, and always the program's own `by TechNet Solutions` line. The TechNet logo and mascot never appear on a branded page; a shop that set no name keeps the TechNet name and pictures and only changes colours and texts.
- **Colours:** every colour on the page comes from `Brand::theme()`, so a test covers them all: for all six palettes and six accents (none, orange, near-black, white, the band colour, red) text, grey text and gold are at least 4.5:1 on the page, band, card and raised card; the accent is at least 3:1 on all four; button text is at least 4.5:1 on the accent and on the pressed accent. `fit_accent` now also checks the raised card. The one exception is today's blue button on the default look (below 3:1 on the raised card), kept on purpose: the owner chose "exactly today's TechNet look".
- **Escaping:** `decorate` escapes `& < > " '` in every text, in every field, with seven adversarial strings (script, quote break-out, `</title>`, `</style>`, `<!--`, entities). Counts of `<script`, `</title>`, `</style>` (plus our own one), `<!--` and event attributes are unchanged from the plain page, and the credit appears once. Unknown palette, layout or accent text never reaches the style block. In a real browser (`test_page_branded.py`), a name and every text set to `</title><script>window.__x=1</script><img src=x onerror=window.__x=2>` shows as plain text: no script ran, no dialog, no element made. (The shop name is limited to 32 characters and the tagline to 60 by the data model, so the page shows the kept part.)
- **Rebuild:** the cached page is built again when the price counter or the new branding stamp (hash of `published.txt` and `images.txt`; the draft is not part of it) changes, so Publish and Restore take effect on the next page load without a restart (browser test: publishing changes the page and its ETag; deleting `published.txt` gives today's page hash again).
- **Browser test** `test_page_branded.py` (Env offset 165, **177 checks, 0 failures**) runs all 18 page states at 360 by 740 with a published branding: shop name and tagline in the header, tab title, credit visible, **the same controls as the unbranded page in every state**, every line of the unbranded page still present except the four replaced ones, no TechNet name besides the credit, contact and hours visible, the logo loads, no request for a TechNet picture, idle shows promo, welcome, rules, accent button and palette colour, and the page after paying shows no promo or rules. The states and helpers are shared with `test_page_golden.py` through `test_page_golden_cases.py`. CI runs it next to `test_brand_public.py`.
- **Nothing else moved:** `test_flow.py` 216 checks, 0 failures; `test_brand_public.py` 20/0 (its "page is still today's" check became "the page is the branded one now"); `test_brand_pack.py` 19/0. `bash scripts/check_security_rules.sh` passes. `page.html` is still 25,575 bytes (the budget change to 40 KB is for group 5). Money path untouched: no change to `core.rs`, `roll.rs`, `ledger.rs`, `boxlink.rs`, `voucher.rs`, `reconcile.rs`; the only change in `http.rs` is how the page is built and when it is built again.
- **Not tested here:** a real phone, the Android and iPhone captive-portal sheet, and the size of the cross-compiled router program (the footprint test measures the committed binaries; this code is built by CI on `beta`).

## Group 5: layouts, two languages and the customer's switch
- **Red first:** `cargo test --release f049_` after the new tests and before the code: 5 failed (layout structure, both-language blocks, the page script); the changed older tests passed only after I corrected them (ledger). **Green:** 184 router tests; `cargo fmt --check` and `clippy -D warnings` clean.
- **Layouts** (`brand_page.css`, chosen by the class on `<body>`; same page, other heading and spacing): **Classic** (today's header band), **Banner** (centred logo, name and tagline, accent line under it), **Compact** (smaller header, smaller picture and spacing, the house rules folded into a "House rules" line), **Poster** (a big heading in the shop's accent colour with contact and hours in it, and the coin button stuck to the bottom of the screen). They follow the candidate sketches in structure, not pixel for pixel: the sketches had their own plan cards, but the real page keeps its plan tabs and price list unchanged in every layout. Compact puts the tagline in the header and keeps hours in the footer; Poster has no footer line because contact and hours are in the heading.
- **Browser test** `test_page_layouts.py` (**385 checks, 0 failures**): 4 layouts x 6 palettes x 2 text sets (normal, and the longest every field allows, with unbroken 60 to 140 character words) at 360 by 740, with six accent choices rotated through (palette accent, orange, near-black, white, teal, red). In each: coin button, plan tabs and price list are on the page; the credit, the name and the language button show; nothing spills sideways; **tapping the coin button sends the start message**; and every piece of text measures at least 4.5:1 against what is behind it (the heading gradient is measured against both its colours). It also walks all 18 page states in every layout: the same controls as the unbranded page, plus the language button (and in Compact the folded rules line), credit visible, no sideways scroll. This test found one real fault: a long unbroken word in any owner text made the whole page wider than the screen; every owner text now wraps anywhere.
- **Two languages:** every owner text (tagline, welcome, contact, rules, hours, promo) can have an English and a Filipino version. Where the two differ the page holds both and the customer's button swaps them without reloading; a missing Filipino text shows the English one; a text that exists only in Filipino is hidden in English; the shop name is one for both. The choice is remembered on the phone (`localStorage`, `pp-lang`) and starts as **English** (today's page is English; the phone's own language is not guessed). The page's built-in wording is turned into Filipino by `brand_fil.js` as the page writes it (76 fixed sentences and words, 21 sentences with numbers or plan names in them, durations "3 hrs" to "3 oras"); anything not listed stays English, never blank. All of it is only added to a branded page: the unbranded page has no switch and no script (golden hash unchanged).
- **Browser test** `test_page_languages.py` (**102 checks, 0 failures**): English first with the button offering Filipino; one tap gives the Filipino page (shop texts, house rules heading, the built-in wording); the choice survives a reload; tapping back gives the English page **line for line identical** to before; a text without Filipino stays English and a Filipino-only promo shows only in Filipino; then **32 page states** (the 18 golden ones plus 14 more: pause captions, almost out of time, a voucher being bought, slowed HyperSpeed, a pause deadline and others) and **15 answers** to a voucher code or a pause are checked for English words (a list of 39 common English words must not appear anywhere on the page), the controls are the same in both languages, and the credit is still visible.
- **Escaping:** unchanged rules, and now the same for the Filipino versions and for the attribute that holds both versions (escaped twice because it holds markup): the payload test sets all seven adversarial strings in both languages of every field.
- **Budgets (Q5):** `page.html` itself did not grow (25 KB of 28), because the branded additions are separate files with their own budgets in `router/tests/test_footprint.py`: `brand_fil.js` 9 of 14 KB, `brand_page.css` 3 of 6 KB. The raise of `page.html` to 40 KB that Q5 allowed is therefore not needed and not made. The programs are measured when CI builds them on `beta`.
- **Nothing else moved:** golden page 24/0 (unchanged), `test_page_branded.py` 177/0 (updated for the language button), `test_brand_public.py` 20/0, `test_flow.py` 216/0. Money path untouched (no change to `core.rs`, `roll.rs`, `ledger.rs`, `boxlink.rs`, `voucher.rs`, `reconcile.rs`).
- **Decisions I made that you may want to change:** (1) the page starts in English whatever the phone's language; (2) the spoken coin sounds ("5 pesos", "Insert coin now") stay English, because most phones have no Filipino voice; (3) the saved voucher file stays English; (4) in Filipino the "check you are on the TechNet Wi-Fi" line says "the shop's Wi-Fi", but the English line on a branded page still says "TechNet Wi-Fi": I left the English wording alone because changing it is a change to the page's own text, and I recommend a small follow-up for it; (5) the Filipino wording is a draft, in `evidence/filipino-wording.md` for you to read row by row.
- **Not tested here:** a real phone (the touch targets, the sticky Poster button on Android and iPhone browsers, the captive-portal sheet's own small browser), and whether Filipino readers find the wording natural: that is the sign-off below.
